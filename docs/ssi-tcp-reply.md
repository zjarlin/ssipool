# 双节点实验 TCP 返回包规则

双节点临时防火墙只放行监听目标端口时，会丢弃落入保护区间的客户端返回包。本轮在同一 ESXi 的两个独占 VM 上固定 TCP 源端口，直接记录到：服务端接受 SYN 并发出 SYN-ACK，客户端随后命中原有端口区间丢弃规则。新增共用规则生成器补齐了限定对端的返回方向，握手与双向回显通过。

这是实验网络配置修正，不是内核协议修复。之前原子实验 `pair-off-b` 没有保存连接四元组，**不能据此断言这就是那次超时的唯一原因**；旧失败记录不修改。回环环境此前已记录相同风险，本轮修正的是双节点临时规则遗漏，见 [实验入口说明](../scripts/ssi-lab/README.md)。

## 为什么只放行目标端口不够

实验链的默认规则丢弃目标端口 `37710–37773` 和 `40000–40063`。实际两节点另加的临时规则只允许已知对端访问 `37710`、`37711`、`40000`、`40001`。宿主自动分配 TCP 源端口的范围为 `32768–60999`，没有保留端口列表，与上述保护区间重叠。

例如客户端使用源端口 `37742` 连接服务端 `37710`：请求的目标端口是 `37710`，能够通过；SYN-ACK 的目标端口却是客户端的 `37742`，不匹配四端口例外，最终被区间规则丢弃。监听器本身已正常启动，等待监听就绪或增加重试不能消除这个配置问题。

新增 [lab-firewall.py](../scripts/ssi-lab/lab-firewall.py) 只生成规则文本，供实验运行器在核对身份与快照后应用。每个明确 IPv4 对端对应两条临时规则：

- 请求：对端源 IP，目标为四个实际监听端口。
- 返回：同一对端源 IP，源为四个实际监听端口，目标落入两个受保护区间。

不依赖 conntrack 表达式，不调整默认丢弃规则，也不允许整段来源网段。它是受信实验对端之间的静态端口例外，**不是协议认证或有状态防火墙**；其他服务、其他拓扑仍需独立规则设计。当前私有原子运行器已改用该生成器，按两条唯一注释回收规则，并继续要求实验前后防火墙 JSON 完全相同。

```sh
python3 scripts/ssi-lab/lab-firewall.py 192.0.2.12 sshpool-example
```

该命令不执行 nft。调用者应先保存原链、核对没有同标签规则，再应用输出；结束后只按本次规则句柄删除，并比较原快照。地址和标签会经过校验，不接受 CIDR、回环地址、换行或 shell 片段。

## 固定端口对照

网络探针在两台原版 `6.8.0-147-generic` VM 上执行。每个方向都独立创建真实监听和客户端 socket；[probe-tcp-reply.py](../scripts/ssi-lab/probe-tcp-reply.py) 核对 132 字节回显，记录失败时的 TCP 状态。抓包只包含指定两端和本次端口；nft 跟踪记录同一四元组实际经过的规则。

| 规则 / 条件 | 两个方向的结果 | 关键证据 |
| --- | --- | --- |
| 旧规则，源端口 36042 | 均成功 | 双向数据和一致回显 |
| 旧规则，源端口 37742 | 均失败 | SYN 已接受，返回 SYN-ACK 命中区间 drop |
| 旧规则，源端口 40042 | 均失败 | 同上，覆盖另一保护区间 |
| 新规则，源端口 37742 | 均成功 | 返回包命中限定 reply 规则 |
| 新规则，源端口 40042 | 均成功 | 同上，完整回显 |
| 新规则，来自非指定对端的本机连接 | 均拒绝 | SYN 命中原区间 drop，没有 SYN-ACK |
| 新规则，对端访问未选用的 37743 | 均拒绝 | SYN 命中原区间 drop，没有 SYN-ACK |

共 14 组完整对照。失败组由用户态 1.5 秒等待截止，客户端停在 SYN_SENT；不能把它写成内核自然返回 ETIMEDOUT。探针在数据核对后用 RST 释放自身 socket，避免固定源端口遗留 TIME-WAIT；该实验不验收优雅 TCP 关闭。

首批六组快速成功连接的回显和 nft 跟踪有效，但 tcpdump 内核缓冲尚未交付，文件中只有 PCAP 头。它们继续作为六份**采集不完整、拒绝验收**的记录归档。采集器改用 `--immediate-mode` 后，以新标签完成这六组；空抓包判定没有放宽。

## 原生 DSM 回归与恢复

另在相同 PF30 内核和既有原子探针上运行一轮双端回归。实验期间仅临时将两台 VM 的 `ip_local_port_range` 设为 `37742 37773`，让自动分配的客户端端口必然落入旧规则的保护区间。运行器保存原范围、实际活动范围和恢复值，并记录原子批次前后的真实 TCP 连接。

每端 4,096 次 LOCK XADD 的合并返回值必须严格覆盖 0–8,191；最终两端计数与哨兵一致，完整跟踪、同代际原生关闭和进程清理仍由原子检查器验证。这个样本只验证修正后的实验通路，不替代公平性、取消、完整 Linux 客体或跨物理容量验收。

本次已通过上述核对：节点零实际出站为 `37762 → 37711`，节点一为 `37746 → 37710`，对端同时记录到对应入站连接。两端都退出零，原源端口范围在重启前已恢复。

完成后恢复原 `32768–60999` 源端口范围、原防火墙和原版内核，核对机器身份、启动文件哈希、GRUB 与无实验线程、跟踪及 TCP 残留。Lima 构建机继续运行。

## 离线重放

[证据清单](evidence/ssi-tcp-reply-20261109.json) 保存所有成功、预期拒绝和不完整采集记录、原始 PCAP 字节、nft 跟踪、规则快照、实际探针及采集器源码，以及原生回归与恢复记录。

[check-tcp-reply.py](../scripts/ssi-lab/check-tcp-reply.py) 直接解析 PCAP 的 IPv4/TCP 头与数据，核对 SYN/SYN-ACK 序号、双端握手对应、回显、零内核丢包、nft trace id 对应的四元组与终态规则。它不以文本摘要或 success 字段代替抓包，也不把两端时间戳相减成网络延迟。

```sh
python3 scripts/ssi-lab/check-tcp-reply.py docs/evidence/ssi-tcp-reply-20261109-legacy-n0-37742.json.gz
python3 scripts/ssi-lab/check-tcp-reply.py docs/evidence/ssi-tcp-reply-20261109-fixed-n0-37742-b.json.gz
python3 -m unittest discover -s scripts/ssi-lab -p 'test_tcp_reply.py'
```

源码和运行记录均有 SHA-256；测试破坏包长度、握手序号、丢包统计、命中判定、对端限制、回显及恢复状态，确保错误证据被拒绝。实验发生在同一物理宿主的隔离 VM，不能证明跨物理可用性、长期稳定性、业务容器或失节点恢复。
