# 带代际和总期限的原生 DSM 关闭

PF28 在两台专用实验 VM 上完成了原生 KVM 的关闭协议验证：每台二十种场景，另有一次真正跨两台 VM 的双向页面传输与关闭。该证据使用没有 vCPU、没有磁盘的 KVM，不能代替 QEMU 设备清理或完整工作区验收。两台 VM 仍位于同一物理 ESXi，没有验证跨物理机容量、持久化或故障接管。

先看 [场景](../features/170-ssi-transport.feature)，再看 [内核补丁](../scripts/ssi-lab/experiments/kernel-dsm-close.patch)、[采集器](../scripts/ssi-lab/probe-kernel-close.py)、[独立检查器](../scripts/ssi-lab/check-kernel-close.py) 与 [完整证据](evidence/ssi-kernel-close-20261108.json)。补丁在 PF25 传输封闭候选之上应用，编译为独立的 `7.1.0-rc3-sshpool-gvm-pf28`，不进入默认安装或 CLI 运行时准入。

## 关闭顺序

研究接口 `KVM_DSM_CLOSE = 0x4018AEFB` 接受二十四字节参数：版本一、零 flags、非零 generation、一至三万毫秒 timeout、零 reserved。所有参与者须使用同一 generation。仍有固定页面或在途固定操作时拒绝关闭；已封闭的普通 ioctl 不能重新进入。

1. 封闭本地普通 ioctl，等待已经准入的调用真正返回。
2. 建立独立管理连接，与所有节点交换 PREPARE。管理处理器不占用数据连接的分发锁，页面反向请求仍可完成。
3. 等待所有管理入站连接登记，由根线程收尽 accept 队列并关闭监听器，固定本次关闭的连接集合。没有首帧、只收到半帧的连接也在集合内。
4. 等待本地传输空闲并原子封闭页面准入；成功后才允许入站 CLOSE 得到确认。
5. 两组出站数据连接逐一 CLOSE/ACK，等待全部已接受的数据连接完成关闭，再交换 READY 和 FINISH。
6. 全部出站先关闭写方向，再读取 EOF；入站只有完成本连接关闭、对端 FINISH 和本地全节点 READY 后，才接受帧边界 EOF。
7. 唤醒根线程，等待它释放全部入站连接并发布 `root_done`，随后 ioctl 才能成功返回。

从建连到根线程回收共享同一个绝对截止时间。半帧 EOF、错误确认、晚到页面请求与已经锁存的错误均不得变成正常关闭。非阻塞建连在连接前发布完整 socket 对象，故障路径可取消 SYN_SENT；已发布对象仍由原生命周期回收。

## 实测结果与边界

| 场景 | 观测 |
| --- | --- |
| 跨两台 VM 的正反向 8192 字节读写 | 实际页面及 SHA256 匹配，双方关闭约 16.84 / 16.33 ms，均返回零 |
| 同宿主两个 KVM 正常关闭 | 两端分别约 20 ms；根线程回收先于成功返回 |
| 已准入写入等待另一节点 unpin | 关闭期间仍观察到 active=1；释放 pin 后真实写入返回，才封闭传输 |
| 非法参数、仍有 pin、根线程定向取消 | 精确验证参数集合、EBUSY 和取消故障传播 |
| 对端不存在、建连 SYN 被丢弃 | 分别返回连接拒绝与约 1.52 s 总期限超时 |
| 未分类连接、八字节半帧、八个缺槽请求 | 无法完成关闭，超时取消；清理 VM 之前线程已经全部退出 |
| 错误 generation / ACK 阶段、CLOSE 后页请求 | 保留世代或协议错误，不能成功 |
| 缺失 ACK、缺失 FINISH、半个 ACK | 同一总期限超时并回收连接 |
| 各阶段延迟 600 ms | 总计约 1.52 s 终止，不给每个阶段重新计时 |
| 真实发送压力 | 一个线程等待 socket 发送缓冲，七个线程等待同连接发送锁，在途数为八；约 1.51 / 1.54 s 超时并全部回收 |

检查器重新解析真实 ioctl 输入、原生返回、完整页面字节与受控对端固定帧；按线程配对入口/返回，核对每个已接受连接的阶段与 EOF，要求 `root_done` 在成功返回之前。跟踪头部、逐 CPU 事件数和 kprobe 漏采计数都必须完整。测试会篡改这些真实记录，验证遗漏根线程、提前成功、错误 ACK、伪造页面及延长期限均被拒绝。

## 保留的失败与纠正

PF26 已完成跨 VM 页面传输和关闭，但其监听集合冻结与完成通知仍需加强。PF27 的一轮正常关闭中，两个 ioctl 都返回零，却留下一个冻结的根线程：完成状态更新后没有唤醒等待者。PF28 统一阶段更新与唤醒，并增加根线程回收确认；旧失败记录与构建来源保留在新证据内。

最初的根线程取消探针使用进程级信号，不能代表内核 `send_sig` 的定向取消。后续改为 x86 `tgkill` 并在 PF28 两端验证。检查器也使用明确的 Linux errno 常量，避免 macOS 上不同的 errno 编号误判。

发送压力的前两版准备阶段失败，未执行关闭验收。第一版错误地要求同连接八个线程都进入 socket 发送等待；线程快照进一步确认，反复读取同一页会移交所有权并触发反向取页，尚未形成发送压力。最终版本对 2048 个不同页各请求一次，以实际线程栈和原生在途计数确认压力成立。所有失败、原探针版本和执行哈希均保留，没有覆盖记录或筛选最佳耗时。

这项工作解决原生页面传输的关闭握手。后续 [限定 QEMU 关闭实验](ssi-qemu-close.md) 已独立验证本轮 virtio-net 与 virtio-blk 配置的设备清理、路由排空、原生关闭与回收；任意设备生产者、时钟恢复、跨物理资源聚合、Ceph、Docker、数据库与接管仍是独立未完成项。
