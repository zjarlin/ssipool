# PF23：固定页面生命周期与关闭入口

PF23 修复普通 ioctl 已返回但设备仍持有 DSM 页面引用时，关闭检查错误放行的问题。页面未释放或固定调用尚在执行时，`KVM_DSM_IOCTL_DRAIN` 返回 `EBUSY`，不封闭入口；调用者仍能解除固定，随后再申请封闭。**这只是完整关闭协议的前置条件，不代表整机正常关闭或业务接管已经完成。**

后续 [PF24 解除进展实验](ssi-pin-release.md) 复现并修复了本文版本在取页持锁期间阻塞旧引用解除的问题；本文实现与证据保留为 PF23 历史对照。

先看 [需求场景](../features/150-ssi-device-memory.feature)，再看 [补丁](../scripts/ssi-lab/experiments/kernel-dsm-pin-lifecycle.patch)、[探针](../scripts/ssi-lab/probe-pins.py)、[检查器](../scripts/ssi-lab/check-pins.py) 和 [原始证据](evidence/ssi-pin-lifecycle-20261106.json)。实验仅使用同一物理 ESXi 上的两台专用 x86 VM，不访问公司数据、生产数据库或业务磁盘。

## 复现与修复

PF22 两台节点均复现：固定一页后，合成对端的真实 KVM 读页请求持续等待；此时普通 ioctl 已归零，DRAIN 返回成功，后续 unpin 被 `ESHUTDOWN` 拒绝。对端直到探针清理仍无响应。旧内核的部分成功 MEMPIN 会返回正数，本次对照按非负成功记录，保留内核原始返回事件。

PF23 为 VM 增加读引用、写引用和在途固定操作计数。计数单位是每页、每类型的引用次数：同一页固定两次计两次，跨页请求分别计数；这不是唯一页数、物理 `FOLL_PIN` 数量或已锁定内存字节数。

固定调用在参数复制和等待槽锁之前取得专用准入令牌，直到完整返回才释放。DRAIN 在同一自旋锁下检查在途固定操作和引用，再决定是否封闭，避免固定操作已准入但尚未产生页面引用的空窗。控制查询自身不计入普通调用。

MEMPIN 持有内存槽锁，并在获取它之后进入 SRCU。先检查整个解除范围，错误类型、重复解除或部分无匹配的范围返回 `EINVAL`，不先释放前面的有效引用。增加引用途中取页失败，则仅撤销本次已增加的引用，保留之前的引用。每页计数在增减前检查上下界；溢出防护目前只有源码与编译验证，没有动态饱和测试。

有引用时，内存槽删除、移动、标志变化和新增别名均在发布 INVALID 槽之前返回 `EBUSY`。当前保护是保守的全 VM 限制：其他不相关槽也不能重配置。继承原实现对没有 DSM HVA 槽的范围跳过处理的行为；已存在 HVA 槽但客体反向映射缺失则返回 `EFAULT`。

## 查询接口

VM ioctl `KVM_DSM_PIN_STATUS` 为 `0x8020aef9`，输出 32 字节，布局为 `u32 version, u32 active_ops, u64 read_refs, u64 write_refs, s32 error, u32 reserved`。版本为 1，保留字段为零。普通入口封闭后仍可查询；真实 VM 故障后标准 KVM 管理入口会拒绝继续使用，不能假定此时还可读到零计数。

这是一份本地瞬时快照，不证明设备后台活动停止，也不证明分布式请求全部完成。QEMU 仍未调用新的 DRAIN、PIN_STATUS 或传输状态接口。

## 验证范围

同一探针分别在两台实验机执行以下场景，记录真实 KVM 返回、内核函数事件、逐 CPU 跟踪完整性、原始 ABI 与网络帧；本机单元测试重新计算这些证据并拒绝篡改：

| 场景 | 验证内容 |
| --- | --- |
| PF22 对照 | 页面仍阻塞时错误封闭，unpin 返回 `ESHUTDOWN` |
| PF23 读页服务 | DRAIN 返回 `EBUSY`，unpin 成功，对端收到正确页面，随后封闭成功 |
| PF23 引用生命周期 | 跨页、读写混合、重叠引用、错误类型、部分无匹配、重复解除及内存槽保护 |
| PF23 在途操作 | 第一页已固定、第二页等远端响应时拒绝封闭；完整返回后仍拒绝，解除全部引用后才成功 |
| PF23 回滚 | 第二页反向映射缺失时撤销本次第一页新增引用，保留原有引用，修复映射后可继续使用 |

直接探针中连接清理可能产生旧有 DSM 断连日志；这不作为正常网络关闭通过的证据。完整客体回归另记录单节点、双节点 SSH、时钟、共享内存、PAUSE、SFTP 和关机结果，使用原有 250 ms 定时器门槛，不能用退出码零掩盖宿主错误。

## 完整客体回归结果

使用同一 `qemu-system-x86_64-router-drain-1` 二进制，各运行一次单节点和双节点，未重跑筛选较好结果：

| 项目 | 单节点 | 双节点 |
| --- | --- | --- |
| SSH、共享内存、PAUSE、SFTP | 完成 | 完成 |
| 三轮定时器最大耗时 | 20.22 ms | 264.93 ms，超过原 250 ms 门槛 |
| QEMU 退出码 | 0 | 两端均为 0 |
| 宿主 DSM 关闭错误 | 无 | 两端仍有 `ktcp_receive` 错误 |
| 完整 SSI 验收 | 不适用 | 失败 |

双节点启动门槛和 QEMU 路由屏障通过，但不能覆盖定时器超限与内核关闭错误。总实验耗时 101.44 秒不是编译吞吐；也没有证据能将本次延迟变化归因于固定页面补丁。历史 PF20/PF22 的结果原样保留。

## 尚未覆盖

- 在途固定操作、页面锁、全局 DSM 锁与远端响应仍可能长期等待。未实现整个固定操作的截止时间、取消和复杂反向依赖死锁处理。
- 尚未动态验证 32 位兼容调用、计数溢出、大规模并发槽修改、真实设备复位及异步 DMA 生命周期。
- 没有协调设备 fd、mmap、irqfd、定时器、后台线程和最终版本化 DSM CLOSE/ACK；持有 VM fd 的 QEMU 关闭顺序仍需调整与证明。
- 未验证持久化磁盘或 Ceph，未安装 Docker、PostgreSQL、Redis、sub2api；没有跨物理机内存容量相加、性能相加或故障接管证据。

在 PF22 后应用 GPL-2.0-only 的本补丁，单独构建 `-sshpool-gvm-pf23`。本轮复用中断前已完成的构建，核对零 fuzz 补丁重放与实际编译源一致；配置仅改变版本后缀。默认构建流程不应用研究补丁，原 Ubuntu 默认启动项及旧内核文件保留。
