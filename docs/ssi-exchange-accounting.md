# PF21/PF22：出站事务与缓存响应

PF22 为 DSM 增加完整出站计数、连接内活跃事务登记、缓存响应计数与查询。它修复了 PF21 在编号耗尽时的无限循环。**这些能力服务于后续关闭协议；当前仍没有整机安全关闭、Ceph、Docker、数据库或跨物理机容量汇聚。** 两台专用 x86 实验 VM 位于同一物理 ESXi。

先读本文，再看 [需求场景](../features/170-ssi-transport.feature)、[检查器](../scripts/ssi-lab/check-exchanges.py) 和 [原始证据](evidence/ssi-exchange-accounting-20261106.json)。历史 PF20 的定时器 431.58 ms、RTC 中断丢失以及关闭错误继续保留，不能用新探针通过覆盖它们。

## 计数和编号的边界

出站计数从 `kvm_dsm_fetch` 等待建连之前开始，覆盖连接登记、发送、响应接收、元数据复制、首次故障锁存和事务退休。普通调用和服务线程产生的反向请求都计数；不能用 socket bank 判定它们是否属于外部操作，因为失效请求也可能使用普通连接。

PF20 的 ioctl 入口封闭不禁止已有服务线程继续反向取页。入站计数从请求解析与校验后开始，直到处理器完成；它不包含仍在 socket 中、尚未解析的字节。三个计数在同一把锁下查询，但 **本地瞬时零计数不是分布式终止证明**：其他节点仍可能发送请求，设备后台任务也可能继续访问内存。

旧代码使用全局静态编号数组与 32 槽响应缓存，编号数组还与允许的节点上限不匹配。候选改为每条连接独立的 Linux IDR：只登记仍存活的事务，跳过通配编号 255。收到别的活跃事务的响应时，将帧挂在该事务上并增加缓存计数；原事务复制、释放后才减少计数。故障回收单独记录，不能称为消费成功。

未登记、重复或已经退休且尚未复用编号的响应返回 `EPROTO`，中止实例并唤醒等待者。复制缓存响应仍检查实际接收缓冲区容量。16 位编号可能复用，当前没有认证、世代防重放保证，不能把上述校验称为网络安全协议。运行实验前仍需独占节点和访问隔离。

## 查询 ABI

新增 VM ioctl `KVM_DSM_TRANSPORT_STATUS`，编号 `0x8020aef8`，32 字节：

```c
/* 输出 1 */
u32 version;
/* 完整出站操作 */
u32 exchanges;
/* 尚未消费或丢弃的响应 */
u32 cached_responses;
/* 已解析且尚未处理完的入站请求 */
u32 inbound_requests;
s32 error;
/* 输出零 */
u32 reserved[3];
```

该查询不计入普通 ioctl 准入令牌，入口封闭后仍可查询；真实故障使 KVM 管理入口失效后，查询返回 `EIO`。因此故障清理的依据包括完整内核事件与已退出线程，不能假装故障后仍成功查询到零。PF20 的 DRAIN/STATUS ABI 不变。动态验证仅覆盖原生 x86-64 调用，QEMU 尚未调用这些管理接口。

## 真实 KVM 探针

PF21 和 PF22 各在两台实验 VM 执行以下六类探针。页面对端是受控回环协议端点；内核、请求处理器、取页与内存复制都是真实 KVM 路径。

| 场景 | 验证 |
| --- | --- |
| 普通出站写入 | MEMCPY 等待远端页面时出站为一；响应后页面内容正确、计数归零。 |
| 反向取页与缓存 | 封闭 ioctl 后两个服务线程向同一所有者取页；实际观察到出站二、缓存一、入站二，再消费响应并归零。 |
| 未登记响应 | 注入编号 50000 的完整响应；原请求保留 `EPROTO`，线程在探针清理前退出。 |
| 重复响应 | 将另一活跃事务的完整响应发送两次；第一次进入缓存，第二次导致故障，原事务随后丢弃缓存。 |
| 半帧取消 | 只发送长度字段，真实线程睡在 TCP 接收中；关闭 VM 后回收等待者。 |
| 建连失败 | 对端没有监听器，`ECONNREFUSED` 仍有完整出站开始、故障、结束证据。 |

缓存实验先发送八字节长度，从真实内核栈和探针确定持锁读者，再发送另一活跃事务的完整响应及当前事务的下一帧长度。读者缓存前者后继续等待半帧，保证查询时缓存仍存在。检查器要求真实半帧栈、正确事务编号、原始 ABI、页面字节和完整事件，不以纯用户态计数替代。

每个事务的登记、接收、退休必须在同一连接，结束事件必须晚于响应处理。缓存减少由 `ktcp_receive` 还是 `ktcp_end_transaction` 调用分别核查，区分成功消费和故障丢弃。跟踪总数、逐 CPU 计数与 kprobe 命中数必须一致；丢事件、残留任务或伪造快照均拒绝。

## 编号耗尽：保留旧失败并验证修复

PF21 的跳号循环会分配 255、删除它、继续分配。当另外 65,535 个编号全部占用时，唯一可分配的仍是 255，因此循环无法结束。小规模 KVM 探针通过不能覆盖这个边界，PF21 不作为最终候选。

PF22 先暂时占住 255，再进行一次分配，随后释放 255；编号用尽时返回 `ENOSPC`。该分支最多调用分配器两次。

[边界夹具](../scripts/ssi-lab/experiments/idr-exhaustion.c) 使用 Linux 原有 `tools/testing/radix-tree` 用户态环境，链接真实 IDR，实现函数直接从两份内核源提取。它运行于 arm64 Lima，启用 AddressSanitizer 和 UndefinedBehaviorSanitizer；单线程锁与未走到的网络中止路径使用替身，**不证明 65,535 个并发 KVM 取页操作**。

旧版填满全部可用编号后超时五秒，修复版返回 errno 28。随后释放编号 40000，成功重新分配，全部删除后 IDR 为空，分配器节点残留为零，无 sanitizer 报错。证据保存两个版本的标准输出、退出码、提取函数、构建日志、输入和二进制哈希。

复现时在固定版本 Linux 源码的 `tools/testing/radix-tree` 目录中，将证据中的 `allocator_capture.extracted.<版本>` 写为 `sshpool-ktcp-allocator.inc`，将夹具复制为独立的 `.c` 文件。继承该目录 Makefile，添加 `<目标>: <目标>.o $(CORE_OFILES)`，安装其 `liburcu-dev` 依赖后编译；用五秒期限执行旧版，修复版应自行成功退出。此测试不能在普通 macOS Python CI 中冒充执行；CI 离线核查保存的真实结果。

## 客体回归与剩余工作

同一候选分别进行一次普通单节点与一次双节点客体回归，沿用 250 ms 时钟门槛及 RTC/watchdog/DSM 错误检查，没有重跑挑选通过记录。

| 回归 | 总用时 | 三轮最大定时器读数 | 结果 |
| --- | ---: | ---: | --- |
| 普通单节点 | 11.20 秒 | 20.19 ms | SSH、时钟、内存、PAUSE、1 MiB SFTP 往返与关机通过。 |
| 双节点 | 85.20 秒 | 103.44 ms | 上述操作完成，QEMU 双向路由屏障完成，两端退出码零；两侧宿主仍有 DSM 接收/关闭错误，完整验收失败。 |

本次客体没有触发原 RTC/watchdog 错误门槛，但仍记录了 `vmstat_shepherd hogged CPU` 工作队列告警。过去的 RTC、watchdog 和 431.58 ms 定时器失败原样保留；一次运行不能证明本补丁修复了它们，也不能据此宣称性能提高。总用时包含启动与检查，不是编译吞吐基准。QEMU 退出码为零不能代替最终 DSM 关闭验收。

仍需协调设备 fd、mmap、irqfd、定时器、DMA 固定页面与后台生产者；所有需要后续 ioctl 的 unpin 和清理须先于入口封闭。QEMU 的路由屏障目前早于部分设备清理，不能立即关闭内核 DSM。

跨节点协议仍缺请求链终止、最终版本化 CLOSE/ACK、故障优先级，以及建连、半帧、发送和占满处理线程时的整体期限。不能先将 VM 标为死亡再期望调用正常关闭的管理接口，也不能用全局 SRCU 等待替代仍依赖网络的请求排空。

缓存超长响应与失效确认的动态验证、完整 KVM 编号空间并发、编号复用后的旧响应、32 位兼容路径仍需补齐。持久磁盘 I/O、Ceph、Docker、PostgreSQL、Redis、sub2api、超过单机内存的工作集、不同物理主机与故障接管均未验收。

## 构建与复核

在 PF20 后依次应用 GPL-2.0-only 的 [事务补丁](../scripts/ssi-lab/experiments/kernel-dsm-exchange-accounting.patch) 和 [耗尽修复](../scripts/ssi-lab/experiments/kernel-dsm-exchange-id-exhaustion.patch)，使用独立的 `-sshpool-gvm-pf22` 后缀。配置仅改变版本后缀，零 fuzz 重放须与实际编译源一致。默认构建流程不自动应用研究补丁。

```sh
python3 scripts/ssi-lab/check-exchanges.py probe.json
python3 -m unittest discover -s scripts/ssi-lab -p 'test_exchanges.py'
```

真实探针拒绝错误内核、已有实验进程、跟踪以及实验端口双向的任意 TCP 状态。TIME_WAIT 自然结束后再创建实例。新内核放在实验 VM 独立目录，默认引导仍保留 Ubuntu，旧 `/boot` 文件逐个校验哈希。原公司文件、业务盘和生产服务不参与实验。
