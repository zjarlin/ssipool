# 写授权等待期间的取消与连接复位

PF30 的真实 KVM 实验补上了一个生命周期验证缺口：在授权等待期间定向取消处理线程、取消根线程或复位受控 TCP 对端，页面锁和 VM SRCU 均已在等待前释放，故障线程在探针清理前退出，随后 DSM_MEMCPY 返回 `EIO`。两种取消没有发出页面响应；复位场景有一次页面发送尝试，返回 `EPIPE`，首次错误保留至根线程退出。

这次没有修改研究内核。实验仅使用 VM51 上的一个 KVM 实例和回环合成对端，验证一条 READ 请求；不代表真实双端全部取消竞态、WRITE 请求、多读写者公平性、跨物理容量或故障恢复完成。PF30 仍不进入默认构建和 CLI 准入，严格 SSI 目标保持未完成。

## 如何证明操作确实发生在等待内

沿用 [probe-write-grant.c](../scripts/ssi-lab/probe-write-grant.c) 的 store 模式，内核与二进制哈希都与前轮一致。每次新建 VM，在 `0x1000` 执行 `mov [0x2000], eax; hlt`，要求 HLT、RIP `0x1005`、读回值 1。随后合成节点 1 发送真实的 GFN 2 READ 请求，事务号 42。

[probe-grant-cancel.py](../scripts/ssi-lab/probe-grant-cancel.py) 使用两个独立 trace instance。通知实例的 `trace_pipe` 只触发动作；归档实例完整保留事件，不消费它的缓冲区。两个实例对同一次探针的时间戳可能相差数微秒，因此关联要求同一 PID、相同事件参数和通知时间位于归档等待区间，不能要求字符串逐字相同。

归档记录 `dsm_lock_killable`、`dsm_unlock` 返回、VM SRCU 获取与释放、`schedule_hrtimeout` 入口与返回、信号、故障锁存、发送结果及线程/VM 释放。每个等待区间都必须证明页锁和 VM SRCU 已释放；控制台打印会使用另一个 SRCU，检查器按页锁前的实例地址与真实返回调用点区分。信号必须是对唯一目标的线程定向 SIGKILL；复位必须有 `tcp_send_reset` 事件，匹配采集线程和实际连接四元组。

复位使用 `SO_LINGER={1,0}` 后关闭连接。这个内核的 `tcp_disconnect` 先将状态置为 `TCP_CLOSE`，再以 `TCP_STATE` 原因发 reset；不能凭名字猜测它一定记录为 `TCP_ABORT_ON_LINGER`。复位事件本身必须严格位于同一处理线程的睡眠入口与返回之间，调用开始的用户态标记不能代替它。

## 有限样本结果

[完整清单](evidence/ssi-grant-cancel-20261109.json) 包含六份通过记录、五份未通过完整验收的记录和实际采集源代码。两份取消记录还覆盖定时器与信号的不同先后顺序。

| 记录 | 授权参数 | 等待段数 | 最长实际等待 | 注入至根线程返回 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| control-off-a | 0 µs | 0 | — | — | 正确页面，无授权等待 |
| control-1000-b | 1000 µs | 1 | 0.494 ms | — | 正确页面，随后单独回收 |
| handler-1000-b | 1000 µs | 3 | 0.161 ms | 13.313 ms | 定时器返回 0，下一次检查报 `EINTR` |
| handler-1000-c | 1000 µs | 5 | 0.137 ms | 6.128 ms | 等待返回 `EINTR` |
| root-1000-a | 1000 µs | 6 | 5.883 ms | 6.666 ms | 根线程报 `EINTR`，通知并回收处理线程 |
| reset-1000-d | 1000 µs | 5 | 0.506 ms | 7.119 ms | 醒来后发送失败，根线程保留 `EPIPE` |

所有故障记录都要求八个处理线程和根线程先于 `cleanup_begin` 退出；随后调用 DSM_MEMCPY 返回 `EIO`。实际释放发生在工作进程退出后，`kvm_dsm_free` 必须晚于九个线程退出。没有把“直到主动清理才退出”计入故障传播通过。

1000 µs 是固定授权截止时间的参数，100 µs 是每次请求的相对睡眠参数；实际调度等待可以更长。表中 5.883 ms 的等待完整保留，13.313 ms 也只是该样本的故障传播观察值，均不是最坏响应时间保证。跟踪、调度和内核错误日志会影响这些时间。

合成对端没有实现原生多节点 CLOSE。无故障对照的工作进程明确以 `close_not_sealed/EINVAL` 退出；故障记录因管理调用 `EIO` 退出。检查器明确输出 `native_close_accepted=false`。前轮真实双端原生关闭的证据见 [原子操作](ssi-atomic-grant.md) 和 [TCP 返回规则](ssi-tcp-reply.md)，不能用本轮 fd 回收替代它。

## 保留的失败与采集修正

- `control-1000-a`：静态 `dsm_request_done` 已被内联，注册探针失败，尚未创建 KVM 实例。没有据此声称动态观察到了请求计数递减。
- `handler-1000-a`：确实捕获等待中信号，但立即读取的线程快照仍有线程，未采集故障后的管理调用；不能满足本轮完整验收。后续采集等待实际退出，并主动调用 DSM_MEMCPY。
- `reset-1000-a`：复位调用标记在等待内，但缺少内核 TCP reset 事件，拒绝作为完整的复位时刻证据。
- `reset-1000-b`：TCP reset 已被捕获，两个采集线程的 Python 阶段列表和内核标记顺序却发生竞争，完整重放拒绝。修正只给采集器阶段写入加锁，没有修改内核调度窗口。
- `reset-1000-c`：reset 事件在最后一次睡眠返回后 18 µs 才发生。故障仍传播，但不满足“等待期间复位”，必须保持拒绝。

每次使用新标签，保留当次脚本、原始 trace、逐 CPU 丢失计数、kprobe 命中/漏采计数、宿主日志和防火墙前后快照，没有覆盖失败记录或放宽窗口条件。

## 重放与恢复

[check-grant-cancel.py](../scripts/ssi-lab/check-grant-cancel.py) 从原始事件重建等待区间与资源顺序。[test_grant_cancel.py](../scripts/ssi-lab/test_grant_cancel.py) 破坏信号时刻、锁释放、线程身份、通知、连接四元组、页面内容、发送返回值、故障返回值和丢失计数，要求这些错误被拒绝。错误内核检查必须在创建证据或启动工作进程之前退出。

```sh
python3 -m unittest discover -s scripts/ssi-lab -p 'test_grant_cancel.py'
```

每次实验只临时允许回环接口、回环源地址和 37710/37711 的请求与返回包；结束后按本次句柄删除规则并逐项比较原防火墙。VM51 已恢复 `6.8.0-147-generic`，写授权参数在重启前归零，原启动文件哈希、GRUB、防火墙、端口范围一致，实验进程、TCP 与跟踪清空。VM52 全程保持原版内核，最后再次核对相同状态；Lima 构建机保持运行。恢复记录与编译源哈希随清单保存，历史证据不修改。
