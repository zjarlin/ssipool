# 单条写指令重复缺页与有期限的写授权

最小 KVM 实验把重复缺页绑定到了**同一次写指令执行**：PF29 一次写入有 306 次缺页，PF30 关闭新开关时有 482 次。开启最长 1 ms 的写授权保留后，两端各 320 次写入的样本均没有重复写缺页。完整 Linux 对照中，最大应用等待由关闭时的 330.297 ms 降到开启第二轮的 168.634 ms；第一轮有无法完整归因的跟踪，单独保留。候选仍只用于独占实验，不进入默认构建或 CLI 准入；完整 SSI 未验收。

## 实验如何排除不同调用混在一起

[probe-write-grant.c](../scripts/ssi-lab/probe-write-grant.c) 注册两个 4 KiB 页面，在 GPA `0x1000` 放入固定五字节 `66 a3 00 20 f4`：实模式的 `mov [0x2000], eax`，随后 HLT。每次 KVM_RUN 前重置 RIP、运行状态和唯一递增值；返回必须同时满足 HLT、RIP `0x1005`、本地读回一致。

宿主 `grant_begin value=N` / `grant_end value=N` 标记围住每次 KVM_RUN，静态 `kvm_page_fault` 仅记录探针主线程。相同 RIP 出现在不同编号调用时不再拼接。另一节点使用真实 DSM_MEMCPY 连续读取同一数据页。两端依次各做 64 次无竞争写入与 256 次远端读取竞争写入，再分别读回 320、640，最后以同一代际执行原生 DSM_CLOSE，双方确认后才释放 VM fd。

[check-write-grant.py](../scripts/ssi-lab/check-write-grant.py) 核对节点、PID 启动时间、全局时钟、完整事件计数和逐 CPU 零丢失；要求唯一写指令、调用编号、完成结果、读者活动顺序、跨节点最终数据和关闭代际均一致。它不把两端宿主时间直接相减，也不把缺页跨度称为单次缺页服务时间。

| 内核 / 开关 | 节点 | 写入数 | 有重复缺页的写入 | 单次写入最多缺页 | 最大 KVM_RUN |
| --- | ---: | ---: | ---: | ---: | ---: |
| PF29 单端 | 0 | 64 | 0 | 1 | 0.716 ms |
| PF29 双端 | 0 | 320 | 7 | 15 | 5.669 ms |
| PF29 双端 | 1 | 320 | 130 | 306 | 37.281 ms |
| PF30 单端，0 | 0 | 64 | 0 | 1 | 0.635 ms |
| PF30 双端，0 | 0 | 320 | 39 | 37 | 10.266 ms |
| PF30 双端，0 | 1 | 320 | 41 | 482 | 70.181 ms |
| PF30 双端，1000 µs | 0 | 320 | 0 | 1 | 5.809 ms |
| PF30 双端，1000 µs | 1 | 320 | 0 | 1 | 0.588 ms |

开启后的两个远端读者分别完成 41,013 与 44,620 次读取，没有值倒退，阶段末两端数据一致。这是有限样本的读者进展证据，不是所有读写竞争和任意负载下的公平性证明。

## 候选的边界

在 PF29 后应用 [kernel-dsm-write-grace.patch](../scripts/ssi-lab/experiments/kernel-dsm-write-grace.patch)，只把内核 LOCALVERSION 改为 PF30。新增 `kvm.dsm_write_grace_us`，默认 0，允许 0–1000；两台 VM 均实际拒绝 1001、负数和非数值输入，保持原值。

只有新授予独占写权限时才设置页面的固定截止时间，已有可写权限的快速路径不续期。在此期间，modified owner 暂缓 READ/WRITE 请求，保留原 owner 与 copyset；INVALIDATE 不延迟。等待前释放页面锁和 SRCU，每段请求最多 100 µs 的可中断睡眠，并返回既有取消检查。停止状态绕过保留期。

这里的 1 ms 是授权截止时间上限，100 µs 是请求的睡眠间隔；宿主调度可能使实际等待更长，均不构成墙钟响应上限。期限在客体重新执行前开始，因此也不保证任意调度延迟下必能执行该指令。后续[等待取消与复位实验](ssi-grant-cancel.md)已补充单条 READ 请求在真实等待区间内的线程取消与回环连接复位。更多取消竞态、多读写者公平性和多节点网络故障仍需独立实测。本轮正常关闭不能替代这些验证。

[qemu-pf30-lab-profile.patch](../scripts/ssi-lab/experiments/qemu-pf30-lab-profile.patch) 只把独立 QEMU 实验构建的精确内核身份改为 PF30，保留双节点、四 CPU、KVM 和显式环境开关限制。两个补丁分别沿用 Linux GPL-2.0-only 与 QEMU GPL-2.0-or-later；不是控制器 MIT 许可下的独立实现。

## 完整客体回归

完整结果由本轮[证据清单](evidence/ssi-write-grant-20261108.json)保存，客体仍是同一原版 Ubuntu 内核与 initramfs。每轮采集六次时钟探针、24 个应用定时器，并执行内存压力、用户暂停、SFTP 数据校验和原生关机。原 250 ms 门槛保持不变。

| 运行 | 最大应用等待 | 最长完整写入区间 | 250 ms 应用门槛 | 完整跟踪归因 |
| --- | ---: | ---: | --- | --- |
| control-off-b | 20.383 ms | 0.074 ms | 通过 | 通过 |
| pair-off-a | 330.297 ms | 1,093.278 ms | 失败 | 通过 |
| pair-1000-a | 169.359 ms | 118.586 ms，仅写入者独立诊断 | 应用日志通过 | 拒绝 |
| pair-1000-b | 168.634 ms | 88.258 ms | 通过 | 通过 |

pair-1000-a 的 PID 223 / CPU 0 在 `hrtimer_start` 之后、实际睡眠切换之前就执行了定时器回调，回调上下文仍是 `ssi-clock`。完整跟踪检查器要求每个目标定时器具有唯一睡眠切换，因此继续报“缺少唯一睡眠切换”；原始记录、单独诊断与拒绝结果都保留。该轮应用日志和写入者诊断不包装成完整归因成功。随后一轮独立运行完成全部关联，旧检查器没有放宽。

四轮都完成身份、内存、暂停、SFTP 和原生关机，控制退出 `[0]`，三个双节点运行退出均为 `[0,0]`。双节点 QUIESCE/DRAIN 与内核关闭代际一致。串口仍有 `workqueue ... hogged CPU` 告警；有限样本改善不保证长期尾延迟、无探针扰动下的表现或跨物理机性能。

实验结束后，两台 VM 均恢复 `6.8.0-147-generic`。机器身份、原启动文件哈希、原 GRUB 和防火墙一致；写授权参数在重启前归零，实验进程、跟踪和 TCP 状态已清理。PF29/PF30 一次性 GRUB 入口和临时 QEMU 链接已移除，研究内核产物保留，Lima 构建机继续运行。首次恢复尝试因 TCP 尚未排空在检查阶段停止，没有执行重启；待运行器确认排空后才继续。

## 失败记录与重放

首次最小控制实验完成 64 次写入，但打开的 trace_marker fd 阻止实例删除，未到达原生 seal；记录明确保留为失败。随后关闭 marker，再删除实例，并使跟踪清理失败也不会跳过原生关闭。恢复出的完整跟踪与失败日志保存在源码归档中。

其他准备失败包括 ARM 原生编译器不支持 x86 KVM 结构、节点一启动快照读取超时，以及 QEMU 构建磁盘余量检查拒绝。没有用失败构建运行实验。最终 QEMU 链接到 tmpfs，原 build.ninja 保持不变；普通用户持有的 tmpfs 文件在后续检查时消失，期间没有重启，删除者未单独跟踪。首个完整控制实验被哈希检查挡在启动前，恢复同一归档二进制并改为 root 持有后使用新标签运行。没有重复启动已运行的客体。

全部五份成功最小实验、完整客体归档、编译源快照、运行器和失败记录均随证据提交。测试用零 fuzz 补丁重放核对实际编译源、参数拒绝记录，并主动破坏调用标记、指令、PID、丢失计数、返回值、读者进展和关闭代际。旧证据不修改。
