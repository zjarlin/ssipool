# 双节点原子加法与写授权进展

PF30 在同一 ESXi 的两台实验 VM 上完成四轮并发 `LOCK XADD`：每端各 4,096 次，合并返回值均严格覆盖 0–8,191，两端最终计数为 8,192，相邻哨兵未改变。关闭写授权保留的两轮仍有同一指令重复缺页；开启 1 ms 保留的两轮没有观察到重复缺页。这是有限样本的原子性和双方进展证据，**不是任意负载公平性、跨物理机容量或完整 SSI 验收**。

本轮沿用 [PF30 内核候选](ssi-write-grant.md)，没有修改内核，也没有运行完整 Linux 客体或 QEMU。实验开关默认仍为零，候选不进入默认安装与 CLI 准入。严格目标继续由 [SSI 可行性](ssi-feasibility.md)、`110-pooled-linux.feature` 和 `120-stateful-recovery.feature` 保留。

## 探针与核对方式

[probe-write-grant.c](../scripts/ssi-lab/probe-write-grant.c) 新增可选 `--atomic`。原来的单条 store 模式继续使用原命令协议；本轮另做 64 次 store 兼容回归，由旧检查器重放通过。

原子模式在 GPA `0x1000` 放置 `f0 66 0f c1 06 00 20 f4`，即实模式的 `lock xadd dword [0x2000], eax; hlt`。每次 KVM_RUN 前重置 RIP、EAX=1 和运行状态；返回要求 HLT、RIP `0x1008`，EAX 为加法前计数。GPA `0x2004` 的哨兵为 `0x51a7c0de`。最终数据通过真实 DSM_MEMCPY 在两端分别读取。

控制端先收到双方 `arm` 确认，再并发发送 `go`。逐次保存操作编号、返回计数、退出原因、RIP 与本机 KVM_RUN 耗时。两端 `batch_started` 都先于任何一端的 `writes_done` 被接收；计数交错提供额外的执行进展观察。控制端接收顺序不等于两端指令的墙钟顺序，不能由此计算跨宿主服务延迟。

[check-atomic-grant.py](../scripts/ssi-lab/check-atomic-grant.py) 复用原检查器的 PID、启动时间、完整事件数、逐 CPU 零丢失和调用边界检查，只将原子指令后的 HLT 地址改为 `0x1007`。它还要求每端返回值严格递增、合并返回值唯一且连续、最终计数与哨兵一致、原生 DSM_CLOSE 使用同一代际、双方封闭后才释放 VM、探针退出零，以及参数和防火墙恢复。

## 完整运行结果

每个双端运行总计 8,192 次操作；单端 control-a 为 128 次。耗时是各节点本机测得的单次 KVM_RUN 最大值，不是授权期限或协议响应上限。

| 运行 / 授权保留 | 节点 | 重复缺页操作数 | 单次最多缺页 | 最大 KVM_RUN |
| --- | ---: | ---: | ---: | ---: |
| control-a / 0 | 0 | 0 | 1 | 0.284 ms |
| pair-off-a / 0 | 0 | 31 | 18 | 53.086 ms |
| pair-off-a / 0 | 1 | 13 | 48 | 60.176 ms |
| pair-off-c / 0 | 0 | 56 | 94 | 14.988 ms |
| pair-off-c / 0 | 1 | 77 | 31 | 45.702 ms |
| pair-1000-a / 1 ms | 0 | 0 | 1 | 10.595 ms |
| pair-1000-a / 1 ms | 1 | 0 | 1 | 1.665 ms |
| pair-1000-b / 1 ms | 0 | 0 | 1 | 5.437 ms |
| pair-1000-b / 1 ms | 1 | 0 | 1 | 1.694 ms |

相邻两次本端成功之间，对端最多完成多少次操作，可以观察有限批次内的进展差异。它不覆盖本端第一次成功之前和最后一次成功之后，也不证明等待时间上限。原始全局序列的最长连续段可能只是另一端已经完成后的尾段，因此检查器另报双方首末计数交集内的最长连续段。

| 运行 | 节点 0 两次成功间最多对端操作 | 节点 1 两次成功间最多对端操作 | 计数归属切换次数 | 首末计数交集内最长同端连续段 |
| --- | ---: | ---: | ---: | ---: |
| pair-off-a | 2,461 | 73 | 267 | 2,461 |
| pair-off-c | 215 | 2,008 | 480 | 2,008 |
| pair-1000-a | 113 | 54 | 137 | 113 |
| pair-1000-b | 75 | 84 | 130 | 84 |

例如 pair-off-a 的全序列最长同端段为 3,857 次，但发生在另一端完成之后；不能将这段称为对端饥饿。上述数值受本轮跟踪、调度和有限批次影响，不是无探针吞吐率或长期公平性的测量。

## 启动失败必须保留

pair-off-b 在最初 DSM_MEMCPY 读阶段失败，尚未 arm，也没有执行任何原子操作。节点一报 `ETIMEDOUT`，内核记录连接节点零失败；节点零随后原生关闭报 `ECONNREFUSED`。该轮没有成功 seal，不计入上述四轮通过结果。

旧运行器清理异常遮住了最初异常，但原始记录、stderr、宿主日志与运行器源码均保留。确认两个 worker 已退出后，检查遗留实例 `sshpool_grant_7263` 的 PID 不存在且过滤器只针对该 PID，冻结并保存完整跟踪和统计，然后仅删除该实例。两端参数归零，防火墙恢复，进程与实验 TCP 清空。

后续运行增加了监听端口和源路由的只读快照，并改进异常记录，让清理异常不覆盖初始错误。**连接失败根因仍未确定**，快照和后续成功不能证明已修复。off-c 使用增加快照的运行器，1000-b 使用同时改进清理的版本；源码归档保留各版本。

后续 [双端 TCP 返回规则实验](ssi-tcp-reply.md) 已复现并修正临时防火墙遗漏返回方向的问题。由于本轮失败没有保存连接四元组，不能反向认定 pair-off-b 的具体原因；此处原始失败与判定继续保留。

## 恢复与重放

实验结束后，两台 VM 恢复 `6.8.0-147-generic`；身份、原启动文件哈希、GRUB 和防火墙与启动前一致。写授权参数在重启前归零，本轮 PF30 临时 GRUB 入口移除，实验进程、跟踪与 TCP 清空。研究产物保留，Lima 构建机继续运行。

[证据清单](evidence/ssi-atomic-grant-20261109.json) 绑定五份成功原子记录、store 兼容记录、启动失败与恢复记录、实际编译源和二进制 SHA-256。压缩原始记录可离线重放；[测试](../scripts/ssi-lab/test_atomic_grant.py) 主动破坏跨节点计数、单端顺序、完成寄存器、哨兵、并发屏障和关闭代际，确保错误记录被拒绝。历史证据保持原样。

```sh
python3 scripts/ssi-lab/check-atomic-grant.py docs/evidence/ssi-atomic-grant-20261109-pair-1000-b.json.gz
python3 -m unittest discover -s scripts/ssi-lab -p 'test_atomic_grant.py'
python3 -m unittest discover -s scripts/ssi-lab -p 'test_write_grant.py'
```

真实探针需固定 PF30 的 x86 Linux KVM 实验宿主；普通 CI 只编译探针、检查错误内核拒绝和重放归档。归档运行器绑定本轮实验身份与快照，不是通用部署工具。保留期内取消/断连、多读写者与多节点公平性、无探针长期运行、异构 ISA、跨物理容量、持久存储、业务容器、数据库和失节点恢复仍待完成。
