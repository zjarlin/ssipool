# PF15：宿主定时器延期重装

2026-11-06。PF15 在 KVM 从客体返回、重新开启中断前兑现已有的定时器重装请求。两节点完整跟踪中，中断退出到首次重装的最大间隔从约 90–115 ms 降到 9–14 μs。两次独立启动客体的无跟踪运行各完成三轮时钟检查，仍采用原来的 250 ms 上限。**RTC、watchdog 和 DSM 关闭问题仍存在，完整 SSI 工作区未通过。**

实验仍只涉及同一 ESXi 上的两个专用 x86 VM。没有接入 Ceph、持久块设备、Docker、PostgreSQL、Redis 或 sub2api；不能证明跨物理机资源相加或故障接管。业务主机和公司目录未参与本实验。

## 找到的路径

PF14 的宿主配置启用了 `CONFIG_HRTIMER_REARM_DEFERRED`。在这条 KVM 路径中，VM-Exit 以关中断现场分发宿主定时器；IRQ 返回可以留下 `TIF_HRTIMER_REARM`，而后续 KVM 重新开中断的代码没有调用对应重装函数。已有 `hrtimer_rearm.h` 要求在即将开启中断的 IRQ 返回路径处理该请求。

基线记录显示：同一宿主 CPU 的 `local_timer_exit` 后，`hrtimer_rearm` 延后约 90–115 ms，随后出现期限相等、设备指针一致的 `clockevents_program_event` 和 `lapic_next_event` 调用。这里的间隔全部使用 trace 时间戳；没有拿 `next_event` 的期限值减去 trace 时间。LAPIC 函数入口只证明尝试编程，不证明硬件已经送达中断。

PF15 的 [补丁](../scripts/ssi-lab/experiments/kernel-dsm-host-timer-rearm.patch) 在 `kvm_before_interrupt()` 后、`local_irq_enable()` 前调用已有 `hrtimer_rearm_deferred()`。函数在关中断状态检查并清除当前线程的延期标记，没有请求时不重装。该调用位于通用 x86 KVM 返回路径，**并非仅影响 DSM VM**，因此另跑普通单节点虚拟机回归。没有覆盖 AMD SVM、其他内核配置和生产虚拟化负载。

补丁以 PF14 为基底零 fuzz 重放，结果与实际编译源码逐字节一致；配置除 LOCALVERSION 外不变，QEMU、客体内核和 initramfs 保持原哈希。PF14 的 PAUSE 实验开关仍开启，不能把 PF15 的结果外推到关闭该开关的组合。所有构建哈希见 [公开证据](evidence/ssi-host-timers-20261106.json)。默认安装脚本不自动应用 PF15。

## 同负载跟踪

PF14 与 PF15 均执行一轮四 CPU 时钟探针；宿主 lazy 抢占、每 CPU 64 MiB 跟踪缓冲、相同事件与函数探针集合。四份记录均通过线程身份、全局时钟、事件总数、每 CPU 丢失计数和函数探针遗漏检查。

| 节点 / 宿主 CPU | PF14 中断退出至重装最大间隔 | PF15 对应最大间隔 |
| --- | ---: | ---: |
| 0 / 0 | 89.915 ms | 9 μs |
| 0 / 1 | 91.349 ms | 14 μs |
| 1 / 0 | 100.464 ms | 14 μs |
| 1 / 1 | 115.369 ms | 10 μs |

PF14 两侧分别记录 2,514,262 / 2,310,725 个事件，PF15 为 2,028,569 / 1,713,716。每个最长窗口都匹配到后续期限和 LAPIC 设备。中断内已完成重装、下一次中断前没有重装、窗口边界不完整的情况单独统计，不硬配成延迟。文本时间戳精度为微秒，零间隔不能理解为没有执行成本。

这组结果支持该返回路径的修正，但没有测量有效计算吞吐，也没有保证所有中断、调度或网络等待都已消除。诊断窗口只有一轮；完整无跟踪验收仍执行三轮，没有降低原门槛。

## 无跟踪回归与失败保留

两次双节点运行各有 96 个跨 CPU 时钟样本、12 个请求 20 ms 的定时器，最长分别为 **151.481 ms** 和 **80.182 ms**。两次有限样本都没有时钟倒退或超过 250 ms。两次均保留内存、用户态 PAUSE、SFTP 与退出记录。普通单节点对照的 12 个定时器最长约 **20.206 ms**。

首次双节点运行的 RTC 读取失败，第二次启动记录无效日期 `2000-00-00`。带跟踪的 PF15 运行还出现 watchdog 跳过检查。DSM 关闭继续报告接收 `-104` / `-4`；QEMU 进程退出码为零不能把这些协议错误变成干净关闭。SSH 在客体断电时返回 255，需要结合串口关机与 QEMU 退出确认，不能单凭该返回值判断关机失败或成功。

普通单节点对照只验证本次配置；不能推出双节点稳定，更不能据此认为性能接近算力相加。完整 SSI 仍须通过 RTC、时钟、正常关闭、持久 I/O、容器、数据库、多物理机容量和故障恢复验收。

## 采集器磁盘不足与证据管理

PF15 首轮采集在节点 0 导出 JSON 时遇到 ENOSPC，留下损坏文件。节点 1 的完整跟踪后来取回，但整轮仍记作失败，不用单侧成功覆盖失败。原文件与 SHA-256、异常栈和失败运行结果都保留。

只对本任务创建的实验跟踪文件做归档：先取回、逐份核对 SHA-256，再移除 VM 上的重复副本。采集器新增空间预检，按每 CPU 缓冲区八倍加 128 MiB 预留文本导出余量；它是保守预检，不能保证并发写盘时绝无 ENOSPC。导出异常仍传播，清理流程覆盖写入 JSON 开头失败的情况。失败记录不会被分析器接受。

重跑时两侧先同时停止跟踪，再导出文件，避免把一侧导出开销混入对侧窗口。新的实验驱动即使某侧导出失败，也继续收集另一侧结果和退出状态。空间预检前后的采集器版本分别记录，新增检查没有改变事件集合或缓冲大小。

## 复核与恢复

```sh
python3 scripts/ssi-lab/check-host-timers.py node0-host-timers-trace.json
python3 -m unittest discover -s scripts/ssi-lab -p 'test_host_timer*.py'
```

完整原始跟踪保存在私有实验目录。公开证据保存哈希、完整性统计、分析摘要与每 CPU 最长五个窗口；较长窗口会注明省略事件，摘要不能冒充完整 trace 重放。合成测试覆盖配对、跨 CPU 边界、探针遗漏、缓冲丢失和空间不足，只验证工具行为，不代替实机记录。

实验结束恢复默认 Ubuntu，核对节点身份、GRUB 环境、原防火墙、QEMU/DSM/跟踪残留和存储状态；研究内核文件保留但不设为默认。Lima 构建环境保持关闭。恢复与 Ceph 检查结果也保存在公开证据中。
